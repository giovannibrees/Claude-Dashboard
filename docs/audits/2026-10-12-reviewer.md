# Code audit: reviewer pass, 2026-10-12

Scope: whole repo (`cloud/agent-hub.html` first, then `server.js`, `lib/`, `bin/`, `public/`).
Method: read every file, reproduced the server findings against a scratch `HUB_DIR`.
Line numbers refer to branch `selftest` at commit 2e1bc32. Security-flavoured findings are
included where they are also bugs; the security auditor owns the full list.

**Counts: critical 0, high 3, medium 11, low 12.**

## High

### H1. cloud/agent-hub.html:911, 616, 642 - old open items fall off the 400-item window
`subscribe('items', ..., orderBy('timestamp','desc').limit(400))` is the only source for Needs you,
Deliveries, Flags, Ideas, the tiles and the prune button. Status items are never removed from the
cloud DB, so after about 400 newer items (10 agents posting status every 2h is roughly 3 days) an
unanswered non-reversible approval (e.g. the plan approval) or a parked idea disappears from the page.
The CEO never sees it and the agent waits forever. Tiles undercount for the same reason.
Fix: subscribe separately to items with `needs_me == true && status == 'open'`, to delivery/audit/idea
statuses, and keep the `limit` only for the feed.

### H2. cloud/agent-hub.html:333, 353, 607-608, 628 - saved filters hide Needs you
Filters persist in localStorage and `needs` is built from `S.items.filter(passes)`. With a filter left
set, the tile says "3 Need you" while the list says "Nothing needs you right now." (hard-coded).
A filter value that no longer exists in the select (renderFilters line 513) still filters but shows
"All". Fix: never filter the Needs you list (filter the feed only), and drop stale filter values.

### H3. server.js:211-220 - no Host check, DNS rebinding reaches the whole API
The same-origin test compares `Origin` to `Host`, both attacker controlled under rebinding. Reproduced:
`POST /api/message` with `Host: evil.example` and `Origin: http://evil.example` returns 200, and
`GET /api/state` answers any Host. A web page the user visits can read all items, send directives to
agents, and call `/api/connect`, which writes `.claude/settings.json`, `CLAUDE.md` and runs `git init`
in any folder. Fix: reject requests whose Host is not `localhost:PORT` / `127.0.0.1:PORT`.

## Medium

### M1. cloud/agent-hub.html:601-606, 513-518, 896-899, 917 - every snapshot re-renders everything
Six subscriptions plus a 60s timer each call `render()`, which rewrites `innerHTML` of the filters,
agents, projects and 150 feed cards. Agent heartbeats make this happen every few seconds. An open
select (priority, filters, IT skill), a focused checkbox, or a half-selected text loses state.
Fix: coalesce renders (one per animation frame / 250ms), skip a section when its HTML is unchanged.

### M2. cloud/agent-hub.html:316, 377 - "running" threshold shorter than the loop pace
`STALE_MIN = 30` but the protocol paces loops at about 30 min (lead audits) and 60 min (blocked).
Agents flip between running and idle, and blocked agents always read as idle. Fix: threshold per
state (blocked 75 min, working 40 min) or let agents write their next expected check into `agents`.

### M3. cloud/agent-hub.html:728-736 - project creation can overwrite and half-write
The duplicate-name check reads `S.projects`, which is empty until the first snapshot lands; `set` on
an existing project/agent doc resets `last_seen` and state. Project and agent docs are written one by
one, so a failure midway leaves a project with missing agents that cannot be re-created (name taken).
Fix: disable the form until the first snapshot, use a batch write or create-if-absent.

### M4. cloud/agent-hub.html:88 - side rail is sticky but can be taller than the viewport
`.rail { position: sticky }` with several agents and project cards exceeds the screen; its lower part
is unreachable until the page end. Fix: `max-height: calc(100vh - 92px); overflow: auto`.

### M5. cloud/agent-hub.html:681-683 - answer is two separate writes from a stale snapshot
`answers/<id>` is set, then `items/<id>` updated. If the second fails, the agent already has an
answer while the card still shows buttons. If the agent auto-resolved the item in the meantime
(protocol 4-hour rule), the CEO click overwrites that answer. Fix: check the item's live status
with `if_version`/a transaction, write both in one batch.

### M6. lib/hub.js:275-295 + bin/hook:93 - every tool call scans all answer files
`pendingFor` runs on each PostToolUse, reads and parses every JSON in `answers/` and every directive
file. `cleanup` only deletes after 30 days, so cost grows with history. Fix: keep an index (answer
files named by agent), or only rescan when the directory mtime changed.

### M7. lib/hub.js:240-247 - agent state is a lock-free read-modify-write
Hook calls for one agent overlap (parallel tools, Stop plus PostToolUse). Both read the file, both
write, one update is lost; a lost `seen_answers` entry makes an answer or directive be delivered
twice. Fix: lock file or append-only per-event files merged on read.

### M8. server.js:190-193, 221-224 - `/file` serves any file an item points at
`allowedFile` accepts every absolute path named in any item's `attachments`/`links`; `post-item`
accepts any existing path. Reproduced: attaching `/etc/hostname` makes `/file?path=/etc/hostname`
return 200. `.html`/`.svg` are served as `text/html`/`image/svg+xml` on the dashboard origin, so a
planted file runs script with access to `/api/*` (same origin). Fix: only serve under the project repo
and `HUB_DIR`, send `Content-Disposition: attachment` and a CSP `sandbox` for html/svg.

### M9. lib/connect.js:25, lib/hub.js:49-51 - invalid settings.json is silently replaced
`readJson(sp, {})` returns `{}` on any parse error, so connecting a folder with a hand-edited
`.claude/settings.json` that is not strict JSON overwrites it with only the hub hooks. Fix: on parse
error abort and tell the user (or back up the file first).

### M10. lib/hub.js:132-135 - URL attachments are always rejected
`path.isAbsolute('https://...')` is false, so the `else if (!/^https?:/ ...)` branch is unreachable and
`post-item --attach https://x/y.png` fails ("attachment must be an absolute path", reproduced). The
rest of the code (post-item, UI) is written to accept URLs. Fix: test `^https?:` first.

### M11. bin/task:244-251, 277-287 - roles are not enforced
Protocol: only the lead sets `done`; only the owner submits for review. `task done` checks only that
the checks passed, `task review` does not check `t.owner === me.agent`. Any agent can close or
resubmit another agent's task. Fix: compare `me.role`/`me.agent` in those two commands.

- L5. lib/hub.js:159, cloud:651 - feedback such as "30 minutes is fine" on a one-question item becomes `per_question {"30": "minutes is fine"}`; only parse when the item has batched questions.

- L7. Duplicated logic in three places: `parsePerNumber`, `roleOf`, `MEANING`, protocol checks (cloud page, `lib/hub.js`, `public/app.js`). They have already drifted (`recommendations` handling differs). Share one module for the local version.
- L8. cloud:781-782 - two consecutive `if (t.id === 'add-toggle')` blocks; merge.
- L9. bin/task:266-267 - failed check with an empty owner makes `tell` exit 1 and `execFileSync` throws after the task was already saved; guard `t.owner`.
- L10. bin/hook:102 - `tokenTotals` reads the whole transcript at each Stop.
- L11. cloud page - `info` status items are never archived (the local server archives after 48h); the DB only shrinks if the CEO presses "Delete them" and eventually hits `quota_exceeded`.
- L12. cloud:541 - attachment `<img src>` may point at any https URL, so an agent can make the CEO's browser load a tracking URL; limit to the hub's asset host.

## Checked and fine

HTML escaping in the cloud page and `public/app.js` is consistent (`esc` on every interpolation,
`safeUrl` blocks `javascript:`, hex values validated). `writeJson` is atomic. The auto-proceed and
scope-freeze rules in `bin/auto-proceed` and `bin/project` match the protocol. Tests: the repo has
none (`package.json` has only `start`), so findings above were verified by reading and by running the
server and CLI against a scratch `HUB_DIR`.
